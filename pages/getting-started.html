事前準備

Cloudflare Pagesを始めるために必要なものは非常にシンプルです。

📧
Cloudflareアカウント

無料で作成できます。クレジットカード不要。メールアドレスのみでOKです。

🐙
GitHubまたはGitLabアカウント

ソースコードを管理するリポジトリが必要です。どちらも無料で作成できます。

📁
Webプロジェクト

HTMLファイルだけでもOK。React、Vue、Nuxt等のフレームワークも使えます。

📌 対応フレームワーク例

React / Vue.js / Nuxt.js / Next.js / SvelteKit / Astro / Gatsby / Hugo / Jekyll / Eleventy / Angular / Remix など主要フレームワークを自動検出してビルド設定を提案します。

ステップ1: アカウント作成

まずCloudflareのアカウントを作成します。

1

Cloudflareサイトにアクセス

dash.cloudflare.com にアクセスし、「サインアップ」をクリックします。

2

メールアドレスとパスワードを入力

有効なメールアドレスと安全なパスワードを入力してアカウントを作成します。

3

メール確認

登録したメールアドレスに確認メールが届くので、リンクをクリックして確認を完了します。

4

ダッシュボードへ

ログイン後、Cloudflareダッシュボードが表示されます。左サイドバーから「Pages」を選択します。

ステップ2: プロジェクト作成

Pagesダッシュボードから新しいプロジェクトを作成します。

1

「新しいプロジェクトを作成」をクリック

Pagesダッシュボードの「新しいプロジェクトを作成」ボタンをクリックします。

2

「Gitに接続」を選択

「Gitに接続」オプションを選択し、GitHubまたはGitLabを選びます。

3

GitHubアカウントを認証

OAuthでGitHubにサインインし、Cloudflareがアクセスできるリポジトリを選択します。特定のリポジトリのみに制限することも可能です。

4

デプロイするリポジトリを選択

一覧からデプロイしたいリポジトリを選択し「セットアップの開始」をクリックします。

ビルド済みのファイル（HTML・CSS・JS等）を直接アップロードする方法もあります。

Wrangler CLI 
# Wrangler CLIを使った直接アップロード
npx wrangler pages deploy ./dist \
  --project-name=my-project

# または特定のブランチとして
npx wrangler pages deploy ./dist \
  --project-name=my-project \
  --branch=staging

直接アップロードはCI/CDツールからのデプロイや、Gitを使わない場合に便利です。

ステップ3: ビルド設定

フレームワークを自動検出した場合は推奨設定が自動入力されます。 手動で設定する場合の主な設定項目を説明します。

フレームワーク ビルドコマンド 出力ディレクトリ
React Create React App npm run build build
Vue.js Vite npm run build dist
Nuxt.js npx nuxt generate .output/public
Next.js npx next build .vercel/output/static *
Astro npm run build dist
SvelteKit npm run build .svelte-kit/cloudflare
静的HTML （なし） / または public
⚠️ Next.jsの注意点

Next.jsのSSRモードを使う場合は @cloudflare/next-on-pages アダプターが必要です。 また一部のNode.js専用APIはEdge Runtimeでは動作しないため、コードの確認が必要です。

環境変数の設定

APIキーやデータベースURLなどの機密情報は、ソースコードに直接書かず環境変数として設定します。

環境変数の設定方法 
# ダッシュボードでの設定
Settings → Environment variables → Add variable

# ビルド時に利用可能な環境変数
VITE_API_URL=https://api.example.com
NEXT_PUBLIC_SITE_URL=https://mysite.pages.dev

# Pages Functions (サーバーサイド) でのみ使える機密変数
DATABASE_URL=postgres://...
API_SECRET_KEY=sk_live_...

# wrangler.toml での設定例
[vars]
ENVIRONMENT = "production"
💡 本番/プレビュー環境の分離

環境変数は「本番環境」と「プレビュー環境」に分けて設定できます。 開発ブランチのPRプレビューではテスト用のAPIキーを使い、 mainブランチの本番デプロイでは本番用のキーを使うといった設定が可能です。

カスタムドメインの設定

デフォルトでは [プロジェクト名].pages.dev でアクセスできます。 独自ドメインを使いたい場合の手順を説明します。

1

プロジェクトの「カスタムドメイン」タブを開く

Pagesダッシュボード → プロジェクト選択 → 「カスタムドメイン」タブ → 「カスタムドメインを設定」をクリック。

2

ドメイン名を入力

設定したいドメイン（例: www.example.com）を入力して「続行」をクリックします。

3

DNSレコードを設定

ドメインがCloudflare管理下にある場合は自動設定されます。 他のDNSプロバイダーの場合は表示されるCNAMEまたはAレコードを手動で追加します。

DNS設定例 
# CNAMEレコード（サブドメイン用）
NAME: www
TYPE: CNAME
VALUE: myproject.pages.dev

# またはAレコード（ルートドメイン用）
NAME: @
TYPE: A
VALUE: 192.0.2.1  # Cloudflareが指定する値
4

SSL証明書の発行（自動）

DNS設定が反映されると、Let's EncryptによるSSL/TLS証明書が自動発行されます。通常数分〜数時間で完了します。

Wrangler CLIを使ったデプロイ

コマンドラインからデプロイする場合は Wrangler CLI を使います。 CI/CDパイプラインへの組み込みにも最適です。

Wranglerのインストールとデプロイ 
# Wrangler CLIをインストール
npm install -g wrangler

# Cloudflareにログイン
wrangler login

# プロジェクトをビルド
npm run build

# Pagesにデプロイ
wrangler pages deploy ./dist --project-name=my-project

# GitHub Actionsでの自動デプロイ例
# .github/workflows/deploy.yml に以下を追加:
- name: Deploy to Cloudflare Pages
  uses: cloudflare/pages-action@v1
  with:
    apiToken: ${{ secrets.CLOUDFLARE_API_TOKEN }}
    accountId: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
    projectName: my-project
    directory: dist
