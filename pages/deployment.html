ビルドパイプライン全体像

Git pushがトリガーとなり、ビルド・テスト・エッジ配信までが全自動で行われます。 この一連のフローを詳しく追っていきましょう。

🐙
1. Git push
GitHub / GitLab にコードをpush
↓
🔔
2. Webhook受信
CloudflareがGitHub webhookを受け取る
↓
📦
3. ビルドコンテナ起動
分離されたコンテナ環境でリポジトリをクローン・依存関係をインストール
↓
🔨
4. ビルド実行
npm run build など設定されたコマンドを実行
↓
🌐
5. エッジ配信
成果物が300+エッジロケーションにレプリケート
↓
✅
6. デプロイ完了通知
GitHubのコミットステータスが更新。プレビューURLが発行。

ビルド環境の詳細

ビルドは以下の環境で実行されます。

ビルド環境スペック 
OS:          Ubuntu Linux (x86_64)
Node.js:     v18.x（デフォルト）/ v16.x, v20.x 選択可
npm:         最新安定版
Python:      3.x
Go:          1.x
Ruby:        最新安定版
メモリ上限:   6GB
CPU:         最大20分間のビルド時間制限
ストレージ:   25GB（/tmp）

# NODE_VERSIONで切り替え可能
NODE_VERSION=20.0.0

プレビューデプロイ

Cloudflare Pagesの強力な機能の一つがプレビューデプロイです。 mainブランチ以外へのpushや、Pull Requestが作成されると自動的にプレビューURLが生成されます。

🔀
ブランチプレビュー

[branch].[project].pages.dev の形式でアクセス可能。 featureブランチごとに独立した環境が自動生成。

👁️
PRプレビュー

Pull Requestを作成すると、そのコミット専用のプレビューURLがGitHubのPRコメントに自動投稿される。

🔒
アクセス制限

Cloudflare Accessと連携してプレビューURLをパスワード保護したり、特定メールドメインのみに制限できる。

プレビューURL形式 
# 本番デプロイ（mainブランチ）
https://my-project.pages.dev

# ブランチプレビュー
https://feature-login.my-project.pages.dev

# コミット専用プレビュー（不変URL）
https://abc1234.my-project.pages.dev

# カスタムドメイン（本番）
https://www.example.com

CDN配信の仕組み

デプロイされたファイルはCloudflareのグローバルネットワーク全体に分散されます。 ユーザーがアクセスすると、Cloudflareのエニーキャストルーティングが最寄りのエッジノードに自動的に転送します。

スマートキャッシング

Cloudflare PagesはファイルタイプとURLパターンに応じて自動的に最適なキャッシュTTLを設定します。

デフォルトキャッシュ動作 
# ハッシュ付きアセット（長期キャッシュ）
/assets/main.a3f2c1d.js  → Cache-Control: max-age=31536000

# HTMLファイル（短期キャッシュ）
/index.html             → Cache-Control: max-age=0, must-revalidate

# カスタムヘッダーで上書き可能 (_headers ファイル)
/api/*
  Cache-Control: no-cache

HTTP/3 (QUIC) の自動適用

Cloudflare PagesはすべてのサイトにHTTP/3（QUICプロトコル）を自動的に有効化します。

  • UDP上で動作するQUICにより、パケットロス時の遅延を削減
  • 0-RTT接続再開で繰り返しアクセス時の待ち時間をゼロに
  • TLS 1.3を標準採用し、ハンドシェイクを高速化
  • 対応ブラウザではHTTP/3を自動的に使用、非対応はHTTP/2にフォールバック

自動圧縮

テキストベースのファイル（HTML、CSS、JS、SVGなど）は自動的に圧縮されて配信されます。

Brotli圧縮

Gzipより最大20%小さく圧縮可能。対応ブラウザでは自動的にBrotliで配信。

Gzip圧縮

Brotli非対応のブラウザにはGzipで配信。どちらも設定不要で自動適用。

ロールバック

デプロイ後に問題が発生した場合、以前のデプロイに即座にロールバックできます。 ダッシュボードから数クリックで完了し、ビルドの再実行は不要です。

✅ ゼロダウンタイムロールバック

Cloudflare Pagesのロールバックはアトミックに行われます。 すべてのエッジノードが同時に切り替わるため、一部のユーザーが古いバージョン・ 新しいバージョンを混在して見ることはありません。 サービス停止なしに瞬時に切り替えられます。

カスタムヘッダー・リダイレクト

リポジトリのルートに特殊なファイルを置くことで、HTTPヘッダーやリダイレクトを制御できます。

public/_headers 
# すべてのページにセキュリティヘッダーを追加
/*
  X-Frame-Options: DENY
  X-Content-Type-Options: nosniff
  Referrer-Policy: strict-origin-when-cross-origin
  Permissions-Policy: camera=(), microphone=()

# APIエンドポイントにCORSヘッダーを追加
/api/*
  Access-Control-Allow-Origin: https://example.com
  Access-Control-Allow-Methods: GET, POST, OPTIONS

# 特定ファイルに長期キャッシュを設定
/assets/*
  Cache-Control: public, max-age=31536000, immutable
public/_redirects 
# 旧URLを新URLにリダイレクト（301永続）
/old-page    /new-page    301

# SPAのための404フォールバック（重要！）
/*           /index.html  200

# 特定ドメインへのリダイレクト
https://old.example.com/*   https://new.example.com/:splat   301

# 国別リダイレクト（Country変数利用）
/             /ja/          302  Country=JP
/             /en/          302
💡 SPAのルーティング

React RouterやVue Routerを使うSPAでは、/* /index.html 200 のルールが必須です。 これがないと、直接URLを入力した際に404エラーになります。

ビルドキャッシュ

Cloudflare Pagesはビルド間でnode_modulesや依存関係をキャッシュし、 2回目以降のビルドを大幅に高速化します。

📦
node_modulesキャッシュ

package.jsonのハッシュが変わらない場合、npm installをスキップしてキャッシュを利用。ビルド時間を大幅短縮。

🏗️
フレームワークキャッシュ

NextやNuxtのビルドキャッシュも保持。増分ビルドに対応したフレームワークはさらに高速化。
